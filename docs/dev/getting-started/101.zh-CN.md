# agent-runtimes 101

## CLI 为什么各不相同

每个 agent CLI 都是独立长大的，同一个操作长得完全不一样：

| 操作      | opencode                            | claude             | codex              |
| --------- | ----------------------------------- | ------------------ | ------------------ |
| 发 prompt | argv + stdin                        | 只认 stdin JSON    | argv               |
| 流式输出  | `run --format json` 行              | `stream-json` 信封 | `exec --json` 条目 |
| 续接      | `--session <id>`                    | `--resume <id>`    | `exec resume <id>` |
| 思考过程  | `reasoning` part（要 `--thinking`） | `thinking` 块      | `reasoning` 条目   |

照着一家 CLI 写的调用方，换一家就崩。这个库的存在理由就这一句。

## 归一了什么

- **事件**——所有方言映射到 9 种无关事件 `RuntimeEvent`
  （`text_delta`、`reasoning_delta`、`tool_started`……）。parser 只管缓冲，不管进程。
- **拉起**——prompt 走 argv/stdin/文件各随其便；模型、续接、工作区 flag 藏进 adapter 的 `buildArgs()`。调用方永远见不到 CLI flag。
- **发现**——安装、版本、模型、认证、MCP、技能、插件：方法一样，底下各探各的，不知道就诚实报 `unknown`/`[]`。
- **会话**——多个进程共用一个 id；原生 id 从事件流捕获并落盘，可续接。

## 故意不抹平的

CLI 安装形态（npm/pnpm/bun/winget 垫片）、`history()` 的转录文件格式、认证机制——这些是机器的事实，如实暴露而不是糊过去。见[安装发现](../discovery/installs.md)。
