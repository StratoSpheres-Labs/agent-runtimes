# agent-runtimes 101

## Why CLIs differ

Each agent CLI grew up independently, so the "same" operation looks
different everywhere:

| Operation     | opencode                              | claude                  | codex               |
| ------------- | ------------------------------------- | ----------------------- | ------------------- |
| Send a prompt | stdin (flags on argv)                 | stdin JSON envelope     | stdin               |
| Stream output | `run --format json` lines             | `stream-json` envelopes | `exec --json` items |
| Resume        | `--session <id>`                      | `--resume <id>`         | `exec resume <id>`  |
| Thinking      | `reasoning` part (needs `--thinking`) | `thinking` block        | `reasoning` item    |

A consumer written against one CLI breaks on the next. That is the whole
reason this library exists.

## What gets normalized

- **Events** — every dialect maps to 10 agent-agnostic `RuntimeEvent`
  types (see `docs/architecture.md` for the full list). Parsers own
  buffering and never touch process state.
- **Launch** — prompts ride argv, stdin, or files per CLI; model, resume,
  and workspace flags hide inside adapter `buildArgs()`. Callers never see
  a CLI flag.
- **Discovery** — installs, versions, models, auth, MCP, skills, plugins:
  same methods, per-CLI probes underneath, honest `unknown`/`[]` when
  unknowable.
- **Sessions** — one id across many processes; native ids captured from
  the stream and persisted for resume.

## What stays different (on purpose)

CLI installation shapes (npm/pnpm/bun/winget shims), transcript file
formats for `history()`, and auth mechanisms — these are facts about the
machine, surfaced honestly rather than papered over. See
[architecture.md](../../architecture.md) for the model.
